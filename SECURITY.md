# Security reporting and release preparation

Do not post credentials, session tokens, unpublished manuscripts or private review
content in a public issue. Use the repository's private vulnerability reporting
feature when enabled; otherwise contact a maintainer privately before providing
sensitive reproduction material. Use a minimal synthetic project where possible.

The server is intended for local loopback use. Host/origin validation and mutation
tokens remain mandatory for every registered route. File-type metadata does not
replace server-side path, signature, size or permission checks. Bundled extension
code is trusted application code and is not sandboxed.

Before public release, maintainers must enable a private reporting channel and
record its concrete contact instructions here, select a root application license,
and review the release contents/history for private research material. This file
does not claim an already configured reporting channel or published release.
